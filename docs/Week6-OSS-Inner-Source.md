## 라이선스 비교

Node.js와 Kubernetes의 공식 저장소를 사례로 삼아 재사용·재배포 조건, 특허 조항, 고지 관리 부담을 비교했습니다.

| 기준 | MIT · Node.js | Apache-2.0 · Kubernetes |
| --- | --- | --- |
| 사용과 재배포 | 상업적 이용, 수정, 재배포를 허용합니다. 소스 공개 의무가 없습니다. | 상업적 이용, 수정, 재배포를 허용합니다. 소스 공개 의무가 없습니다. |
| 재배포 시 고지 | 사본 또는 상당 부분에 저작권과 허가 고지를 유지합니다. | 라이선스 사본을 제공하고 변경 파일에 수정 사실을 표시합니다. 해당 고지를 보존하고 원본에 NOTICE가 있으면 적용되는 고지 내용을 포함합니다. |
| 특허 | 명시적인 특허 허여 조항이 없습니다. | 기여자가 허여할 수 있는 관련 특허 청구항을 대상으로 명시적 허여가 있으며, 정해진 특허 소송을 제기하면 해당 허여가 종료됩니다. |
| 실제 사례 | Node.js 본체는 MIT를 사용하고, 포함된 외부 라이브러리의 라이선스를 별도로 고지합니다. | Kubernetes는 저장소 루트에 Apache License 2.0을 게시합니다. |

AI SUMMIT에는 **MIT**를 선택했습니다. 현재 공개 산출물인 기획 문서, 와이어프레임, 실습 도구를 수업과 후속 프로젝트에서 재사용하기 쉽게 하고, 재배포 시 저작권과 허가 고지를 유지하는 단순한 조건을 적용하기 위해서입니다. 명시적인 특허 허여가 주요 선택 기준이 되는 프로젝트라면 Apache-2.0을 검토할 수 있습니다. AI SUMMIT의 MIT 라이선스는 프로젝트가 권리를 보유한 산출물에 적용합니다. 외부 코드·이미지·자료를 추가할 때는 해당 자료의 라이선스와 고지 조건을 확인합니다.

- [OSI MIT 원문](https://opensource.org/license/mit) · [Node.js LICENSE](https://github.com/nodejs/node/blob/main/LICENSE)
- [Apache Software Foundation Apache-2.0 원문](https://www.apache.org/licenses/LICENSE-2.0) · [Kubernetes LICENSE](https://github.com/kubernetes/kubernetes/blob/master/LICENSE)

## 조직 내부 Inner Source 도입 로드맵

여러 팀이 같은 사내 도구를 수정할 수 있도록, AI SUMMIT의 문서·와이어프레임을 본뜬 **사내 UX 가이드 또는 개발 도구 한 개**에서 4주간 시범 운영하는 제안입니다.

| 시기 | 담당 | 실행과 확인 기준 |
| --- | --- | --- |
| 1주차 · 준비 | 운영팀과 저장소 관리자 | 사내 GitHub 저장소를 만들고, 조직 구성원에게 읽기 권한을 부여합니다. README·기여 안내·행동 강령·담당자를 등록하고, 권한 없는 외부 계정에서는 접근이 제한되는지 확인합니다. |
| 2주차 · 첫 기여 | 운영팀과 참여 팀 한 곳 | 시작하기 좋은 이슈 2개를 준비합니다. 참여 팀원이 안내만 보고 로컬에서 실행하고, 이슈에 연결된 문서나 예제 변경 PR을 1건 제출합니다. |
| 3주차 · 공동 리뷰 | 지정 검토자와 기여자 | 검토자는 근무일 기준 2일 이내 첫 응답을 목표로 합니다. PR에서 검증 근거를 확인하고, 여러 팀에 영향을 주는 결정은 ADR로 남깁니다. 검토를 통과한 PR 1건을 병합합니다. |
| 4주차 · 평가 | 운영팀과 참여 팀 | 참여 팀 수, 타 부서의 제출·병합 PR 수, 첫 사람 응답 시간을 이슈·PR 기록에서 확인합니다. 참여 팀 1곳 이상, 타 부서 PR 병합 1건 이상, 첫 응답 목표 충족 여부를 바탕으로 확대 또는 개선 후 재시험을 결정합니다. |

운영팀은 우선순위와 병합 권한을 관리합니다. 초기 검토자는 온보딩과 리뷰를 맡으며, 반복적으로 기여한 팀원에게 검토 책임을 위임할 수 있습니다. 이슈는 요청과 진행 상황, PR은 변경과 리뷰 근거, ADR은 팀 간 결정 배경을 남기는 데 사용합니다. 첫 응답 지표에는 봇 안내를 제외하고, 표본이 적으면 중앙값과 함께 건수를 기록합니다.

시범 저장소에는 합성 데이터와 내부 공유가 승인된 자료만 사용합니다. 운영 비밀이나 고객 데이터는 접근이 제한된 원래 시스템에 보관합니다. 내부 저장소에서 만든 자료의 외부 공개는 조직 정책에 따라 별도로 승인받습니다.
